# Reference app analysis

Use the [BAA execution rules](../../../../../EXECUTION.md) already established for this task. Preserve the assigned Windows target, current stage, file ownership and acceptance; do not create a nested team.

Inspect the supplied reference and actual Windows entry flows. Record behavior, information hierarchy, keyboard/pointer actions, loading/error/empty states and window sizing before proposing visuals. Separate observed behavior from assumptions; do not copy private assets or claim unseen screens were inspected.

Map the agreed scope to the existing frontend and Rust host. Reuse common app-brief/user-stories/ux-design only where decisions are missing. A screenshot reference is not permission to scaffold or replace an existing app. Return the reference evidence and selected native-window/web-content boundary.
