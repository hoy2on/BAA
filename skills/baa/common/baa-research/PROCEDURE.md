# Research

[공통 실행 규칙](../../EXECUTION.md)을 먼저 읽는다. BAA가 전달한 선택 플랫폼, 작업 목적, 현재 단계, 파일 소유권과 완료 기준을 유지한다. 플랫폼을 다시 선택하거나 전체 기획을 반복하지 않는다.

후속 스킬은 실행 패키지 루트에서 `python3 scripts/resolve.py --entrypoint <호출 진입점> --platform <선택 플랫폼> --step <단계>`로 조회한다. 반환된 이름과 문서 경로를 사용하며 원본 BAMA·BAWA의 짧은 이름이나 외부 설치 경로를 추정하지 않는다. 반환된 path의 PROCEDURE.md를 읽어 수행한다. 내부 이름을 Skill 도구나 슬래시 명령으로 호출하지 않는다.

공유 문서의 최종 편집자는 BAA 조율자 한 명이다. 플랫폼 담당자는 공유 BRIEF/STORIES/GLOSSARY/연구·검토 문서를 동시에 수정하지 않고 변경 제안과 근거를 조율자에게 반환한다. 단독 실행에서는 현재 담당자가 그 역할을 맡는다.

앱의 사용자 과제, 경쟁 앱의 장단점, 선택 플랫폼에서의 구현 제약을 조사한다. BAMA와 BAWA의 조사 → 병합 → 기획 인계 흐름을 공유한다.

## 1. Frame

조사 질문과 그 결과로 결정할 사항을 한 문장씩 정한다. 기존 BRIEF, 연구 문서와 화면 인덱스가 있으면 먼저 읽는다. 이미 구현된 앱의 국소 문제라면 필요한 API·동작 질문만 조사하고 시장 조사나 신규 기획을 추가하지 않는다.

## 2. Tracks

질문에 필요한 트랙만 선택한다. 제품 방향 조사에는 Market와 Reviews를 포함하고, API 선택에는 Platform과 관련 Features를 중심으로 한다.

- Market: 실제 지원 플랫폼, 가격, 대표 기능이 확인되는 경쟁 앱.
- Reviews: 사람들이 좋아하거나 불편해하는 점. 스토어·포럼 의견과 검증된 제품 사실을 구분한다.
- Features: 공식 설명서, 도움말, 변경 기록에 있는 동작과 제한.
- Design: 화면, 탐색, 입력 방식과 접근성. 대상 플랫폼 차이를 별도로 기록한다.
- Platform: 공식 API, 권한, 지원 OS, 배포·앱 식별 제약과 기존 프로젝트에서 사용 중인 구현.

BAA 조율자가 기존 작업자에게 독립 조사 범위를 배정할 수 있다. 병렬 도구·허용 범위가 없으면 순차로 진행하고, 플랫폼 담당자가 조사 하위 팀을 재귀 생성하지 않는다. 조사자는 파일을 편집하지 않고 출처와 제안을 반환한다.

조사 인계에는 질문, 결정 대상, 플랫폼, 조사 범위, 공식 문서 우선 원칙과 결과 형식을 전달한다. 모든 주장을 `[V]` 출처로 확인, `[K]` 지식에 근거, `[U]` 미확인으로 구분하고 URL과 확인 날짜를 남긴다. 가격·현재 API·지원 버전은 직접 확인한다. 접근하지 못한 자료를 읽은 것처럼 보고하지 않는다.

## 3. Merge

조율자는 질문당 기존 연구 문서 하나를 보완하거나 `docs/research/<topic>.md`에 다음을 기록한다.

- 질문, 선택 플랫폼, 확인 날짜와 조사 범위.
- 경쟁 앱별 장점·불편·출처와 반복되는 사용자 과제.
- 기능 행렬: 기능 / 비교 앱 / 선택 플랫폼 / 이번 범위 포함 여부.
- 결정: 채택 내용, 이유, 근거와 필요한 검증.
- 열린 질문: 결정에 영향을 주는 `[U]` 항목과 이를 확인할 최소 실험.

기능 행렬의 포함 항목은 `user-stories`로 이어지고 중요한 사용자 장점은 결정 또는 수용한 차이로 남긴다. 플랫폼의 저장·동기화 기능이 적합한지 확인하되 도입이나 외부 계정 연결을 조사만으로 실행하지 않는다. Windows에서는 package identity와 OS 가용성, Apple에서는 entitlement·지원 OS, Android에서는 SDK·권한·실행 제한 등 해당 API 조건을 확인한다. 동기화 폴더에 활성 데이터베이스를 두는 식의 운영 결정을 조사 없이 권하지 않는다.

## 4. Hand off

참고 앱을 직접 관찰할 필요가 있으면 해당 플랫폼의 `clone`을 조회한다. 앱·브라우저 조작 환경이 없으면 공개 도움말과 출처가 확인된 화면 자료로 한계를 기록한다. 신규 앱의 개요가 필요하면 `app-brief`로 연결한다. 국소 조사 요청은 조사 결과로 끝낸다.

완료 기준: 선택 트랙의 근거가 병합됐고, 포함 기능과 결정이 출처 또는 명시한 검증 계획에 연결되며, 미확인 사실이 확인된 사실과 구분되어 있다.
